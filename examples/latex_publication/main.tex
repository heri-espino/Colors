\begin{abstract}
This two-column article demonstrates a document-aware Matplotlib workflow.
Figures are generated from dimensions and font sizes measured from this
LaTeX document. One graph is included using PGF, so its text is typeset
with the same LaTeX font configuration as the surrounding paragraphs.
The remaining examples illustrate a vector PDF, rasterized scatter artists,
and six simulated accessibility conditions.
\end{abstract}

\section{What does font matching mean?}
Scientific plots should be designed at their \emph{final physical width}.
The preamble probe measures \verb|\columnwidth|, \verb|\textwidth| and
normal body font size. In these plots, axis labels use the body point size;
tick and legend labels follow a consistent hierarchy.

A PDF produced independently by Matplotlib can have the correct
font \emph{size} without matching its glyphs.
PGF instead instructs LaTeX to typeset text when the figure is included.

\section{Grouped scatter}
A categorical plot should not rely on hue alone.
Figure~\ref{fig:groups} assigns each category a distinct color and marker.
White marker outlines separate overlapping observations without adding
visual weight, and all axis labels use the document's normal 10 pt text size.
All observations in one category keep the same marker. Three groups
use broadly spaced relative luminances so their grayscale variants remain
visibly separated. Legends sit above the data rather than covering points.

\section{Presentation at the final reading size}
Good rendering is not only a question of pixel density. A diagnostic image
can contain the right information and still be unreadable when reduced from
a large preview window to the width of a printed journal column.
Here we deliberately compare two common publication requirements: a
full-page diagnostic dashboard for a main or supplementary result, and a
compact landscape dashboard spanning both columns of the manuscript.

These two uses call for different aspect ratios. Enlarging a figure in a
browser is not equivalent to designing it for physical print dimensions.
The example therefore controls both the size of the \emph{source} plot and
the final figure environment in LaTeX.

\subsection{Full-page dashboard: three time series}
For the three-series plot we reserve a dedicated page. Two dashboard
columns and three rows provide enough width for tick labels, a legend,
and six accessibility views without forcing the reader to zoom into a
single column. The same underlying trajectories are shown in all six
conditions; only the simulated viewing conditions change.

A separate heading sits immediately above each displayed image.
Its horizontal center is aligned to the image rather than to a larger
container, and it uses regular-weight type so it does not compete with
the axis labels. Color, line pattern, and marker shape encode each series
redundantly. Their luminance levels are spread across the available range
because the plot has only three categories.

\subsection{Landscape dashboard across the two text columns}
The grouped scatter illustrates the opposite constraint. Many articles
have room for a full-width figure near the top of a page but not for a
dedicated page of supplemental diagnostics. We therefore arrange the six
views horizontally in three columns and two rows, reducing the height
of the complete dashboard while keeping it wider than an individual
text column.

Unlike the time-series example, these data are categorical point clouds.
The useful question is whether group membership is recognizable after
color transformation. We use fewer observations, larger symbols, and
nonidentical markers, all on a light background. A short legend is placed
outside the plotting region so that a data point cannot be obscured by
text. The grayscale views supply a practical check of luminance separation
as an additional cue.

To demonstrate how this layout behaves in a realistic manuscript,
the following paragraphs intentionally provide enough ordinary body text
to flow beside and below a wide top-of-page float. A reader sees not only
the plot itself but its actual spatial relationship with the paper's
columns, headings, captions and surrounding arguments.

A compact horizontal diagnostic is particularly appropriate when it
supports a result explained in the main text. The original figure may
already show group separation clearly; the dashboard is then a short
robustness check rather than the principal quantitative result. The
location of captions and the final scale of markers should always be
checked after compilation, because a figure that looks spacious in a
large editing window can be difficult to interpret once printed.

The three simulated color-vision deficiencies follow the Machado model.
They are useful stress tests, but viewers differ and the simulation is
not a substitute for user testing. Likewise, the degraded grayscale
panel represents intentionally reduced tonal resolution rather than
a calibrated office printer.

\section{Reproducibility}
The accompanying script uses a fixed random seed, saves a JSON report
with font lookup, physical widths, and audit results, and compiles a
standalone proof confirming that the PDF figure's unscaled width
matches the measured LaTeX column.

Matching nominal point size, using PGF, and inspecting grayscale do not
eliminate a final visual review of dense legends, labels and scientific
clarity.
