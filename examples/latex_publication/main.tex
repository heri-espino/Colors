\begin{abstract}
This two-column article is a reproducible technical presentation of
\texttt{contrastcolors}, a Python library for scientific palette design,
publication-sized figures and accessible visual identifiers. We show
how hue, chroma and relative luminance are chosen; how categorical
graphics can be inspected in grayscale and simulated colour-vision
conditions; how transparent observations interact with backgrounds;
and how a local LaTeX installation supplies document dimensions
and fonts. We compare true-vector PDF/PGF output with intentional
hybrid vector--raster export and construct both a full-page and a
landscape accessibility dashboard. The interactive Palette \& Plot
Studio offers a browser-based path to many of the same choices.
Every result is generated by the associated reproducible script.
\end{abstract}

\section{What is being solved?}
A plot that looks clear on a monitor may become unreadable in a
narrow journal column or a monochrome printout. Different viewers
may be unable to separate its hues. Transparent overlays change
their appearance with the background, and an independently rendered
PDF may have text with the right point size but the wrong font.
\texttt{contrastcolors} provides reusable design and publication
helpers on top of Matplotlib to reduce this repeated manual work.

The workflow is: choose a palette; identify categories with
additional marker and line cues; generate the plot at its final
physical size; inspect grayscale and colour-vision variants;
and export vector, hybrid or raster representations as appropriate.
The final compiled manuscript remains the reference for quality.

\section{How the palette is selected}
\subsection{Hue versus luminance}
The library uses OKLCH hue $h$ (an angle), chroma $C$ and
OKLab lightness $L$ to describe colours, but explicitly targets
\emph{sRGB relative luminance} $Y$ when controlling contrast.
OKLab lightness and relative luminance are not the same measure.
The latter comes from linearized sRGB channels:
\begin{equation}
 Y=0.2126R_{\mathrm{lin}}+
   0.7152G_{\mathrm{lin}}+
   0.0722B_{\mathrm{lin}} .
\end{equation}
For each requested hue and luminance, the library solves for an
OKLCH lightness producing that $Y$. If the requested chroma
cannot be represented inside sRGB, it reduces chroma instead
of silently assuming all vivid colour combinations are available.

\subsection{An explicit contrast ladder}
For opaque colours with ordered luminances, the adjacent
WCAG contrast ratio can be set by construction:
\begin{equation}
 r=\frac{Y_k+0.05}{Y_{k+1}+0.05},\qquad
 Y_k=\frac{Y_0+0.05}{r^k}-0.05 .
 \label{eq:ladder}
\end{equation}
Here $Y_0$ is the starting luminance and $r$ the chosen
adjacent ratio. The number of feasible rows is limited
because relative luminance lies between zero and one.
The hue may change independently at each row without
altering the requested luminance ladder.

The \texttt{ContrastGrid} makes this construction visible:
each row fixes luminance and each column fixes hue.
Choosing one cell per row creates a palette. The live
matrix in Figure~\ref{fig:palettegrid} is generated with
three levels, four hue choices, and an adjacent ratio
$r=1.55$.

\subsection{Defaults and alternative hue rules}
For a small number of unrelated groups,
\texttt{plot\_scheme()} and \texttt{scatter\_scheme()}
can spread the available grayscale luminances widely.
The spacing adapts to the number of colours: two or
three groups receive greater separation than ten.
An explicitly supplied ratio, starting luminance or
named preset is respected instead of replaced.

The Studio offers equidistant hue angles, golden-angle
spacing, analogous hues, balanced-family arrangements,
single-hue schemes and manual selection. Such rules are
starting points, not guarantees of equal perceptual
distance or universal accessibility. For ordered data,
a sequential luminance scheme often communicates
structure better than a set of unrelated categorical hues.

In our main line/scatter demonstration we deliberately
use a fixed Okabe--Ito starting trio---orange
\texttt{\#E69F00}, blue \texttt{\#0072B2}, and
bluish green \texttt{\#009E73}---alongside different
marker and line shapes. These fixed hex values are
\emph{not} being claimed to satisfy
Equation~\ref{eq:ladder} exactly. The independent
luminance-controlled grid is how to request that guarantee.

\subsection{User choices and reusable presets}
These public functions can construct or inspect a
user-defined palette:
\begin{verbatim}
import contrastcolors as cc
p = cc.contrast_palette(
    hues=[25, 155, 275],
    ratio=1.55,
    start_luminance=0.65,
    chroma=0.12,
)
print(p.hex, p.luminances)
print(p.adjacent_contrast)
\end{verbatim}
The user may adjust hue order, colour count,
relative luminance, requested chroma, background,
opacity, markers, line patterns and font settings.
Named designs can be registered with
\texttt{register\_palette()} and reused during the
Python process.

The \href{https://heri-espino.github.io/Colors/studio.html}
{Palette \& Plot Studio} makes these choices interactive
with hue and contrast controls, plotting examples,
grayscale/colour-vision previews and exportable
Python/JSON presets. The browser preview is SVG-based;
the installed Matplotlib renderer remains authoritative
for a submitted publication.

\section{What does font matching mean?}
Scientific plots should be designed at their \emph{final physical width}.
The preamble probe measures \verb|\columnwidth|, \verb|\textwidth| and
normal body font size. In these plots, axis labels use the body point size;
tick and legend labels follow a consistent hierarchy.

A PDF produced independently by Matplotlib can have the correct
font \emph{size} without matching its glyphs.
PGF instead instructs LaTeX to typeset text when the figure is included.

\section{Presentation at the final reading size}
Good rendering is not only a question of pixel density. A diagnostic figure
can contain the right information and still be unreadable when reduced from
a large preview window to the width of a printed journal column.
Here we deliberately compare two common publication requirements: a
full-page diagnostic dashboard for a main or supplementary result, and a
compact landscape dashboard spanning both columns of the manuscript.

These two uses call for different aspect ratios. Enlarging a figure in a
browser is not equivalent to designing it for physical print dimensions.
The example therefore controls both the size of the \emph{source} plot and
the final figure environment in LaTeX.

\subsection{Full-page dashboard: three time series}
For the three-series plot we reserve a dedicated page. Two dashboard
columns and three rows provide enough width for tick labels, a legend,
and six accessibility views without forcing the reader to zoom into a
single column. The same underlying trajectories are shown in all six
conditions; only the simulated viewing conditions change. The paper uses
a color-vision-friendly orange, blue and bluish-green starting palette
with different line and marker shapes; no three colors can guarantee
accessibility for every viewer.

A separate heading sits immediately above each plotted view.
Its center is aligned to the axes and it uses regular-weight type,
so it does not compete with 10 pt axis labels. Color, line pattern, and marker shape encode each series
redundantly. Their luminance levels are spread across the available range
because the plot has only three categories.

\subsection{Landscape dashboard across the two text columns}
The grouped scatter illustrates the opposite constraint. Many articles
have room for a full-width figure near the top of a page but not for a
dedicated page of supplemental diagnostics. We therefore arrange the six
views horizontally in three columns and two rows, reducing the height
of the complete dashboard while keeping it wider than an individual
text column.

Unlike the time-series example, these data are categorical point clouds.
The useful question is whether group membership is recognizable after
color transformation. We use fewer observations, translucent points, 0.22 pt white
outlines and nonidentical markers, all on a light background. A short legend is placed
outside the plotting region so that a data point cannot be obscured by
text. The grayscale views supply a practical check of luminance separation
as an additional cue.

To demonstrate how this layout behaves in a realistic manuscript,
the following paragraphs intentionally provide enough ordinary body text
to flow beside and below a wide top-of-page float. A reader sees not only
the plot itself but its actual spatial relationship with the paper's
columns, headings, captions and surrounding arguments.

A compact horizontal diagnostic is particularly appropriate when it
supports a result explained in the main text. The original figure may
already show group separation clearly; the dashboard is then a short
robustness check rather than the principal quantitative result. The
location of captions and the final scale of markers should always be
checked after compilation, because a figure that looks spacious in a
large editing window can be difficult to interpret once printed.

The three approximate color-vision deficiencies follow the Machado model.
The lines and scatter artists, their titles and their axis labels remain
vectorial in these dashboards; colored values are transformed before
redrawing rather than converting each complete figure into pixels.
They are useful stress tests, but viewers differ and the simulation is
not a substitute for user testing. Likewise, the degraded grayscale
panel represents intentionally reduced tonal resolution rather than
a calibrated office printer.

\section{Reproducibility}
The accompanying script uses a fixed random seed, saves a JSON report
with font lookup, physical widths, and audit results, and compiles a
standalone proof confirming that the PDF figure's unscaled width
matches the measured LaTeX column.

Matching nominal point size, using PGF, and inspecting grayscale do not
eliminate a final visual review of dense legends, labels and scientific
clarity.
